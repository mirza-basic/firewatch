FireWatch on macOS

The menu bar app: a wildfire monitor that sits in the status bar, notifies you when something changes, and keeps a live map one click away.

This is one of three guides

macOS gives you the menu bar app, which no other platform does. For a headless box see FireWatch on Linux; to put the map on a public URL see Hosting FireWatch. Command, setting and troubleshooting references live in the Field Manual.

01 What you need

  • A Mac that stays awake. The app is a menu bar item started by launchd at login. There is no server component — if the Mac sleeps, polling stops.
  • Python 3.14 from python.org. Homebrew's build works too, but the launch agent pins whichever interpreter you install with, so pick one and stay on it.
  • A NASA FIRMS key — free, instant, no approval. Optional: without one you lose VIIRS/MODIS and keep the other two feeds.
  • Very little disk. Six months of a quiet municipality is a 184 KB SQLite file.
Check your longitude first

The fast feed is geostationary and only covers roughly 60°W to 60°E — Europe, Africa, the Middle East, eastern South America. Outside that, FireWatch works on a three-hour delay rather than twenty-five minutes. The Field Manual has the measured numbers.

02 Install

  1. Install the dependencies

    python3 -m pip install rumps pyobjc requests certifi

    rumps and pyobjc build the menu bar item; requests and certifi handle HTTPS.

    Do not substitute urllib

    Several Python builds ship no CA bundle, so anything using the standard library's urlopen dies with CERTIFICATE_VERIFY_FAILED while requests works through certifi. That is why certifi is a hard dependency and why the launch agent pins SSL_CERT_FILE.

  2. Store a FIRMS key

    Request one at firms.modaps.eosdis.nasa.gov/api/map_key/, then put it in the Keychain rather than a file:

    ./firewatch-ctl set-firms-key      # prompted, not echoed
python3 -m firewatch quota        # confirms which key is in use

    No key is committed to the repository. Resolution order is FIRMS_MAP_KEY in the environment, then the Keychain, then firms_map_key in your config file.

  3. Take one poll for a test drive

    python3 -m firewatch poll

    One full cycle in the foreground, with a printed report: which feeds answered, how long each took, what is currently burning. Every source should read [ok ]. Zero detections is a normal, healthy result — most days nothing is on fire.

  4. Install the login agent

    ./firewatch-ctl install

    Generates the launchd plist against your interpreter path and CA bundle, installs it in ~/Library/LaunchAgents/, and starts it. Look for 🌲 in the menu bar.

  5. Fill in some history

    python3 -m firewatch backfill 30   # about 5 minutes

    A fresh install knows nothing about the past, so the longer map ranges are empty. Nothing re-fetches history on its own — this is a deliberate, occasional command.

03 The menu bar

The icon is the status at a glance: 🌲 when nothing is burning, 🔥 when something is. Opening it lists the tracked fires with severity, location relative to the nearest settlement, radiative power and how long ago each was last seen — and gives you Google Maps links, copyable coordinates, and a one-click refresh.

The app runs rumps on the main thread and owns the polling thread, so the menu, the notifications and the map all read the same published snapshot. They cannot disagree with each other.

The landmine that costs the most time

The running agent holds its modules in memory and keeps overwriting the snapshot. Edit code or config without ./firewatch-ctl restart and your change looks like a no-op while the stale output looks like a logic bug.

04 Notifications

Alerts go through osascript, which macOS attributes to Script Editor — so that is what you allow in System Settings › Notifications. Clicking such a notification does nothing.

Install terminal-notifier and they become clickable links straight to Google Maps at the fire's coordinates:

brew install terminal-notifier
python3 -m firewatch test-notify   # sends a sample

FireWatch picks it up automatically; notify.backend() reports which is live. SMS is a separate, independent channel — see the Field Manual, and note that a failed notification never suppresses the text message.

05 Sharing the map

On a laptop, expose publishes the map through ngrok, so there are no ports, DNS or certificates to arrange:

./firewatch-ctl expose      # prints the URL
./firewatch-ctl exposed     # publish state and every tunnel
./firewatch-ctl unexpose

Only the map and its data file are published. The log, database and snapshot stay in a different directory entirely.

Free-tier realities
  • The URL is random and changes every time the ngrok agent restarts — including a URL you have already texted to people. FireWatch rebuilds the tunnel each cycle while publishing is on, but the address will be different.
  • The agent is shared with anything else on the machine that uses ngrok, and a free account allows three endpoints per session.
  • unexpose stops publishing, but the URL keeps resolving until the agent restarts — ngrok never actually closes a file tunnel.

If you want an address that stays put, that is a hosting job rather than a laptop one — see Hosting FireWatch.

06 firewatch-ctl

This wrapper drives launchctl, so it is macOS-only.

CommandWhat it does
installGenerate the plist for this machine, install it, start at login
uninstallStop and remove the login item. Data is kept
start / stopLoad or unload the agent
restartRun after every code or config change
statusService state, plus the last published snapshot
logsTail the log
poll / mapOne cycle; rebuild and open the map
expose / unexpose / exposedPublish the map, stop, show status
sms / test-sms / set-sms-keySMS settings, a test message, store the key
set-firms-keyStore the FIRMS key in the Keychain
sms-add / sms-remove <number>Manage recipients — applies without a restart

Everything else runs through python3 -m firewatch <command>, listed in full in the Field Manual.

07 Files & uninstall

PathContents
~/Library/Application Support/FireWatch/ firewatch.db, snapshot.json, fire-map.html, logs
~/Library/Caches/FireWatch/public/ The only directory ever published. Rewritten every cycle
~/.config/firewatch/config.json Your overrides — never any credential
~/Library/LaunchAgents/ com.firewatch.zavidovici.plist

Keys live in the Keychain (services firewatch-firms and firewatch-httpsms), never in a file. The database is a single SQLite file with no external state, so backing it up is a copy.

./firewatch-ctl uninstall    # stops the agent, keeps your data

To remove everything, delete the directories above as well.
