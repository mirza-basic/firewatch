01 What changes

Exactly one module is platform-specific, and __main__ imports it lazily — so nothing you run here loads it, and nothing you install here needs its dependencies.

PieceOn Linux
Polling, clipping, clustering, alerting, map rendering unchanged pure Python and requests
SMS unchanged the key comes from HTTPSMS_API_KEY
Serving the map unchanged serve is stdlib only
Desktop notifications notify-send where a desktop exists; on a headless host the alert is logged and SMS carries it
Data locations XDG — ~/.local/share/firewatch, ~/.cache/firewatch
The menu bar app macOS only run watch or serve instead
./firewatch-ctl not available use the systemd unit below
Tested, not assumed

Every headless command was verified with no platform tooling on PATH at all and HOME pointed at an empty directory: poll, watch, status, map, serve, quota, buffer and reclip all worked. A missing notification backend logs the alert and returns False rather than breaking the cycle.

02 Install

  1. Two dependencies, not four

    sudo apt install python3 python3-pip     # or your package manager
python3 -m pip install requests certifi

    No rumps, no pyobjc — those build the menu bar and are macOS-only. Optionally add libnotify-bin for notify-send if this machine has a desktop, and shapely + pyproj only if you intend to regenerate the map's buffer band with firewatch buffer.

  2. Supply the keys through the environment

    No credential is committed to the repository, and there is no system keystore in play here — both keys come from the environment:

    export FIRMS_MAP_KEY=your_key_here        # free: firms.modaps.eosdis.nasa.gov/api/map_key/
export HTTPSMS_API_KEY=your_sms_key       # optional, for SMS alerts
export HTTPSMS_FROM=+38761234567          # the Android gateway phone

    For a service, put these in an EnvironmentFile with mode 600 rather than in the unit itself.

    No FIRMS key is a supported state

    VIIRS/MODIS is skipped and reported as [----] rather than [FAIL], and Meteosat and Sentinel-3 — which need no credentials at all — carry the cycle. You lose sensitivity to small fires, not the service.

  3. Take one poll for a test drive

    python3 -m firewatch poll

    Every configured source should read [ok ]. Zero detections is a normal, healthy result. If nothing is ever detected and you are outside Europe, Africa or eastern South America, check the coverage section of the Field Manual — the fast feed is geostationary.

  4. Fill in some history

    python3 -m firewatch backfill 30   # about 5 minutes

    Nothing backfills on its own, so the long map ranges stay empty until you run this once.

03 Run it as a service

Two shapes, depending on whether you want the map served as well:

CommandDoesUse when
watchPolls, alerts. No HTTP You only want SMS, or you serve the files some other way
servePolls and serves the map You want a URL. One process, one unit

deploy/firewatch.service is a ready systemd user unit:

mkdir -p ~/.config/systemd/user
cp deploy/firewatch.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now firewatch
systemctl --user status firewatch
journalctl --user -u firewatch -f
It stops when you log out

A user unit dies with your session unless you tell systemd otherwise:

loginctl enable-linger $USER

For a system-wide install put the unit in /etc/systemd/system/, set User= and Group=, and point FIREWATCH_DATA_DIR somewhere the service account can write — the shipped unit uses %h paths that assume a user install.

Stopping is clean: systemctl stop sends SIGTERM, which FireWatch handles rather than dying on — measured at 0.3 s to a zero exit, not a SIGKILL after the grace period. The log rotates at 2 MB × 3, and also goes to the journal.

Turn ngrok off on a server

If your config carries auto_expose: true from a laptop install, the poller will try to build an ngrok tunnel every cycle, fail, and log a warning every ten minutes. Set "auto_expose": false — the built-in server replaces it.

04 Where things live

Linux follows XDG rather than the macOS layout:

WhatDefaultOverride
Database, log, snapshot, rendered map ~/.local/share/firewatch FIREWATCH_DATA_DIR
The only directory ever served ~/.cache/firewatch/public FIREWATCH_PUBLIC_DIR
config.json ~/.config/firewatch FIREWATCH_CONFIG_DIR

XDG_DATA_HOME, XDG_CACHE_HOME and XDG_CONFIG_HOME are respected where set. The three FIREWATCH_* variables override everything, which is what containers and system services need.

05 Getting alerted

On a headless box the desktop notification has nowhere to go, so SMS is the channel that matters. It runs through httpSMS, where an Android phone you own is the gateway — messages come from your own number.

The two halves are configured differently on purpose:

  • The sender is deploy config. HTTPSMS_FROM plus HTTPSMS_API_KEY, both in the environment. Fixed for the life of the deployment.
  • The recipients are live state. They live in config.json, and sms-add / sms-remove apply to the running service without a restart — the list is re-read at send time, not taken from the snapshot loaded at start-up.
python3 -m firewatch sms-add +38761234567
python3 -m firewatch sms-status     # says exactly what is missing, if anything
python3 -m firewatch test-sms

Numbers must be E.164 — leading +, country code, no spaces. Alert text is transliterated to ASCII: one non-GSM character switches the whole message to UCS-2 and drops the segment size from 160 characters to 70.

If this machine does have a desktop, install libnotify-bin and notifications appear through notify-send. With no backend at all, notify.backend() reports "none" rather than naming something that is not installed, and each alert is written to the log.

06 Verify

python3 -m firewatch status          # last published state
python3 -m firewatch quota           # which FIRMS key is in use
python3 -m firewatch sms-status      # SMS readiness
journalctl --user -u firewatch -n 50

A healthy install shows every configured source as [ok ] and a snapshot timestamp only a few minutes old. If you are also serving the map, /health answers that question directly — see Hosting FireWatch.

Restart after every change

The service holds its modules in memory. Edit code or settings without systemctl --user restart firewatch and the change looks like a no-op while the stale output looks like a bug. The one exception is the SMS recipient list, which is deliberately live.
